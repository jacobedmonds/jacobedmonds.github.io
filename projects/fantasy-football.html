Project Overview

I built a fantasy football draft assistant that combines a Python analytics engine with a Java application to support real-time draft decisions. The project integrates player metadata, average draft position (ADP), and projection data from multiple sources, then uses those inputs to identify player value, positional scarcity, and draft opportunities.

The goal was to move beyond a static ranking sheet and build a repeatable data pipeline and decision-support tool that can update recommendations as players come off the draft board.

Problem

Fantasy football rankings provide a useful starting point, but a draft is dynamic. The value of a player depends not only on projected production, but also on positional depth, replacement-level alternatives, current ADP, and which players have already been selected.

I designed the project around a practical question: How can multiple fantasy football data sources be combined into a system that recommends the best available player as a draft develops?

Data Pipeline

Multi-source player dataset

The analytics pipeline combines player information from multiple fantasy football sources and standardizes those records into a single master dataset.

  • Cleaned 602 ADP records from FantasyPros
  • Integrated Sleeper player metadata including team, position, bye week, and player identifiers
  • Matched 524 player records across the ADP and Sleeper datasets
  • Collected 385 projection records across QB, RB, WR, and TE from CBS
  • Standardized player names, teams, positions, and numeric fields before joining datasets

Player Matching

One of the largest data-engineering challenges was matching players across independent sources that did not always use identical names or metadata. Instead of relying on one exact join key, I used a staged matching strategy.

  • Primary match using name + team + position
  • Fallback match using name + position
  • Unique-name matching when a player could be identified unambiguously
  • Unmatched records retained for review rather than silently discarded

This approach improved coverage while keeping the merge process interpretable and reproducible.

Analytics

Value Over Replacement

Player value is evaluated relative to replacement-level options at the same position rather than using raw projected points alone. This makes it possible to compare players across positions on a more meaningful basis.

Positional Scarcity

The system accounts for the depth remaining at each position. As stronger players at a position leave the board, the cost of waiting can increase, changing the relative value of the remaining options.

ADP Analysis

Average draft position is used as a market benchmark. Comparing projected value with ADP helps identify players who may be available later than their analytical value suggests.

Real-time Recommendations

Draft-board state is incorporated into the recommendation process so the available-player pool changes as selections are made.

Application Architecture

The project separates the analytics layer from the user-facing application. Python handles data preparation and player evaluation, while Java provides the draft interface.
